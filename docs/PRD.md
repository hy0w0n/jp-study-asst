# PRD — SENSE (センセ) · 일본어 한자 학습 어시스턴트

> grill-me 2라운드(11-06 11:20~11:36)로 확정. 바꾸려면 planner로 이 문서를 먼저 고친다.

## 1. 문제 — 내 경험에서
- ① 일본 취업 준비 중 모르는 일본어를 검색·여러 AI 채팅에 나눠 물어봐서 **기록이 흩어진다**.
- ② 물어볼 때마다 **시작 프롬프트와 원하는 출력 형식을 다시 입력**해야 한다.
- ③ 일본 한자는 한국 한자와 **모양·획순이 달라** 쓰는 법을 일본 사이트에서 따로 찾아야 한다. 읽는 법을 모르면 **검색어조차 입력하기 어렵다.**

## 2. 사용자
- 일본 IT 기업 취업을 준비하는 한국인 대학생 (JLPT N3~N2), 이동 중 폰으로 5~10분씩 공부

## 3. 해결 (한 문장)
모르는 한자를 **타이핑·손글씨·사진으로 검색**하면 **획순 화면**으로 이동해 일본식 획순이 진하게 채워지며 그려지고, AI가 정해진 형식으로 **음독·훈독 · 뜻 · 한국 한자와의 차이 · 단어 · 예문**을 알려주는 모바일 웹앱. 입력 3종은 검색 수단이고 주인공은 획순 화면이다. 문법·독해·청해로 확장할 자리를 둔다.

## 4. 90초 데모 시나리오 (확정)
1. 검색창에 `履歴書` 입력 → 칩 3개 → `履` 탭
2. 시트: 획순 재생(2×) → 한 획씩 → AI 카드(음독 リ · 훈독 は(く) · 뜻 · 한국 한자와 차이 · 단어 2 · 예문 1) → 따라 쓰기
3. (손글씨가 되면) 홈에서 `職`을 손으로 써서 후보 중 고르기 → 시트
4. (사진이 되면) 예시 사진 → 칩
5. 학습 탭 → 문법·독해·청해 `준비중` 카드 → "서비스 준비중입니다" 모달 → "다음 단계: 사진·내 한자장·문법·독해·청해" 한 줄
- 발표 환경: 제출 **13:20**, 발표 **14:30**. 노트북 Chrome 기기 모드(375px) 투사 + 폰 실기(손글씨 시연) + 30초 화면 녹화 백업. 네트워크 불안 시 폰 핫스팟.

## 5. 범위 (확정)
개발 시작 11:45 · 기능 동결 **12:50** · 제출 **13:20**. Tier 1 합계 85분이라 예정대로면 13:10에 끝난다. 동결 후에는 진행 중인 Tier 1 작업 마무리와 버그만.

| 티어 | 순서 | 기능 | 예상 | 위험 → 대응 |
|---|---|---|---|---|
| 1 | 1 | 앱 셸: 패키지 설치 + 레퍼런스 조사 → `docs/design.md` → 토큰 + 하단 탭 2개 + 준비중 3개 모달 + 폴리싱 10분 + 첫 배포 | 30분 | 폴리싱 과잉 → 10분 상한 |
| 1 | 2 | 한자 획순: 채워지는 재생 · 한 획씩 · 따라 쓰기 (바텀시트, 일본식 데이터, 가나 포함) | 30분 | 데이터 없는 글자(薔) → 안내 + AI 카드 유지 |
| 1 | 3 | 타이핑·붙여넣기 검색 → 한자 칩 | 10분 | 없음 |
| 1 | 4 | AI 설명 카드 (자동, 스트리밍) | 15분 | 길면 느림 → 단어 2·예문 1 고정, ~450토큰 |
| 2 | S1 | 손글씨 검색: 홈 인라인 캔버스, 한 글자 → `/api/vision` → 후보 5 | 15분 | 인식률 → 후보에서 고르기 |
| 2 | S2 | 사진 검색: 파일 선택 + 예시 사진 버튼 → `/api/vision` | 25분 | 조명·지연 → 예시 사진 |
| 2 | S3 | 내 한자장: 시트의 ☆ → 학습 탭 그리드 → 탭하면 따라 쓰기 (localStorage) | 10분 | 없음 |
| 2 | S4 | 최근 검색 8개 (localStorage) | 5분 | 없음 |

- Tier 2는 **12:50 전에 Tier 1 배포가 끝났을 때만**, 위 순서대로. 못 한 입력 방식(손글씨·사진)은 **버튼 자체를 두지 않는다** (준비중 배지 금지).
- **준비중 (3개 고정)**: 문법 · 독해 · 청해. 학습 탭 카드에 `준비중` 배지, 탭하면 모달: 제목 "서비스 준비중입니다" + 한 줄 + [확인].
  - 문법: "문법 질문과 작문 첨삭을 AI 튜터가 한국어로 설명해 줘요" · 독해: "일본어 기사·공고를 붙여넣으면 후리가나와 요약으로 읽어 줘요" · 청해: "짧은 일본어 음성을 듣고 받아쓰기로 연습해요"
- **제외 (오늘은 화면에도 없음)**: Supabase 동기화·로그인, 결제, JLPT 커리큘럼, 다국어 UI, 자유 채팅 입력창, 한글·로마자로 한자 찾기(AI lookup), 음성 읽기, 연습 통계·간격 반복, 공유·내보내기

## 6. 화면
- 하단 탭 2개: **한자**(`/`) · **학습**(`/learn`). 질문 채팅 화면 없음.
- 홈 `/`: 검색 바(16px↑) → 입력 방식 버튼 `입력 · 손글씨`(S1) `· 사진`(S2) → 결과 칩(낱자, 중복 제거, 가나 포함) → 빈 상태엔 예시 칩 `履歴書 · 面接 · 職` → 최근 검색(S4). 한자·가나가 없으면 "한자나 가나를 입력해 주세요".
- 한자 바텀시트(~75dvh, 내부 스크롤): ① 헤더(글자 크게 + 닫기) ② 획순 300px + 컨트롤(재생 · 한 획씩 · 따라 쓰기 · 1×/2×) ③ AI 카드 ④ ☆ 저장(S3). 열리면 자동 재생 1회(reduced-motion 제외), 따라 쓰기 중 시트 스크롤 금지, 카드 안 한자는 일반 텍스트(시트 중첩 금지).
- 학습 `/learn`: (S3) 내 한자장 그리드 → 준비중 카드 3개.
- 디자인: 셸 단계에서 레퍼런스 조사(5분) → `docs/design.md`(토큰·폰트·간격) → `designer` 스킬 표 갱신 → 구현. 연한 아이보리 배경, 와인색 포인트(순빨강 금지), 텍스트·획은 먹색(순검정 `#000000` 금지). frontend-design은 이 토큰 안에서 타이포·획순 영역 연출.

## 7. 데이터
- 오늘은 서버 DB 없음. 내 한자장(S3)·최근 검색(S4)은 localStorage.
- `supabase/migrations/0001_init.sql`은 그대로 두고 적용하지 않는다. 발표에서 "다음 단계: 계정 동기화(Supabase, 마이그레이션 준비됨)".

## 8. 기술 구조
브라우저(Next.js 16, App Router) → `/api/kanji`(AI 카드, `streamText`, 후리가나 `{漢字|かんじ}` 규약) · `/api/vision`(S1·S2, 이미지 → 한자 후보 구조화 출력) · 획순 데이터 `@k1low/hanzi-writer-data-jp@0.8.0`(jsDelivr, 가나 포함, 薔 없음) + hanzi-writer 3.7
- 모델은 `AI_MODEL`(gpt-5.4-mini) 하나. 새 환경 변수 없음. 설치: hanzi-writer, ai, @ai-sdk/openai, @ai-sdk/react, zod.
- 사진은 브라우저에서 긴 변 1280px로 줄여 보낸다 (Vercel 함수 요청 본문 4.5MB 제한).

## 9. 성공 기준 (제출 기준)
- 폰에서 배포 URL로 시나리오 1·2·5가 끊김 없이 동작 (3·4는 Tier 2 결과에 따라)
- AI 카드 첫 글자 2초 이내, 전체 8초 이내 · 손글씨는 職·私·日 후보 5개 안에 정답
- 테스트 한자 6개(私 必 飛 職 あ ア) 획순 정상, 薔은 "획순 데이터가 없어요" + AI 카드 표시
- 준비중 3개 모달 열림·닫힘, 375px 가로 스크롤 없음, `npm run build` 통과

## 10. 리스크 → 대응
- Next 16 API 차이 → `node_modules/next/dist/docs` 먼저 읽기, hanzi-writer는 타입 파일 기준
- 획순 30분 초과 → 따라 쓰기는 hanzi-writer quiz 기본 동작, 커스텀 금지
- 손글씨·사진 인식 오류 → 항상 후보에서 고르게 + 다시 시도 · 예시 사진
- 시간 부족 → Tier 2를 위에서부터 포기, Tier 1은 동결 후에도 마무리
