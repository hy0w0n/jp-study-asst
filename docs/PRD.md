# PRD — KAKU (가칭) · 일본어 한자 학습 어시스턴트

> 초안. 기능 구상(`planner`) → `/grill-me` → `planner`로 확정한다. 1페이지를 넘기지 않는다.
> 이름 후보: **KAKU(카쿠)** · 히토후데(一筆) · 모지센세(文字先生) — 최종 결정은 킥오프에서.

## 1. 문제 — 내 경험에서
- 일본 취업 준비 중 모르는 일본어를 검색·여러 AI 채팅에 나눠 물어봐서 **기록이 흩어진다**.
- 물어볼 때마다 **시작 프롬프트와 원하는 출력 형식을 다시 입력**해야 한다.
- 일본 한자는 한국 한자와 **모양·획순이 달라** 쓰는 법을 일본 사이트에서 따로 찾아야 한다. 읽는 법을 모르면 **검색어조차 입력하기 어렵다.**

## 2. 사용자
- 일본 IT 기업 취업을 준비하는 한국인 대학생 (JLPT N3~N2), 이동 중 폰으로 5~10분씩 공부

## 3. 해결 (한 문장)
모르는 한자를 **찍거나 · 쓰거나 · 붙여넣으면** 일본식 획순이 진하게 채워지며 그려지고, AI가 정해진 형식으로 읽기·뜻·한국 한자와의 차이를 알려주는 모바일 웹앱.

## 4. 90초 데모 시나리오
1. 앱 열기 → **사진** → 일본어 이력서(履歴書) 양식이나 책 표지를 촬영 → 한자 칩이 뜸
2. `履` 탭 → 바텀시트에서 획이 하나씩 채워지는 애니메이션 + AI 설명(읽기·뜻·한국 한자와 차이)
3. **따라 쓰기**로 손가락으로 써 보기 → (손글씨 검색이 있으면) 손으로 `職`을 써서 찾기
4. 하단의 `준비중` 메뉴를 보여주며 "다음 단계: 일본어 질문 모드(문법·첨삭·면접)" 한 줄

## 5. 범위 (추천안 — grill-me에서 확정)
**Tier 1 · 반드시 (약 2시간)**
- M1 한자 획순: 재생 / 한 획씩 / 따라 쓰기, 일본식 데이터, 가나 포함 → `kanji-stroke`
- M2 한자 검색 — 직접 타이핑 + 사진 → `kanji-search`
- M3 한자 상세 AI 설명 카드: 읽기·뜻·한국 한자와 차이·예시 단어 (프롬프트 입력 없이 자동) → `jp-tutor-prompt`의 `kanji` 모드
- M4 확장 기능 자리: 하단 메뉴 + `준비중` 배지·안내 시트 → `designer`

**Tier 2 · 시간이 남으면 구현, 아니면 준비중으로**
- S1 손글씨 검색 (+15분, 사진과 같은 API)
- S2 내 한자장: 저장 + 최근 검색 (Supabase 익명 로그인) (+20분)

**준비중 (화면엔 있음, 최대 3개)**
- AI 일본어 질문 — 단어·문법·첨삭·면접 모드 (원래 아이디어의 채팅)
- 복습 퀴즈 — 저장한 한자 따라 쓰기 복습
- (S2를 못 하면) 내 한자장

**제외 (오늘은 화면에도 없음)**
- 회원가입·소셜 로그인, 결제, JLPT 전체 커리큘럼, 다국어 UI

## 6. 화면
- `/` 홈 = 한자 검색 (검색 바 + 입력·사진·손글씨 버튼 + 최근 검색)
- 한자 바텀시트 = 획순 + AI 설명 카드 + 저장
- 하단 탭: **한자 · 질문(준비중) · 내 한자장(S2 또는 준비중)**

## 7. 데이터 (`supabase/migrations/0001_init.sql`, S2에서 사용)
- `saved_items` (kind = kanji): 저장한 한자 / 최근 검색은 `saved_items`에 note='recent'로 넣거나 별도 테이블 — planner가 결정
- `conversations`, `messages`: 질문 모드가 준비중이면 테이블만 두고 미사용
- 모두 RLS: 본인 행만 읽기·쓰기

## 8. 기술 구조
브라우저(Next.js) → `/api/vision`(사진·손글씨 → OpenAI gpt-5.4-mini 비전) · `/api/kanji`(AI 설명) · Supabase(익명 Auth + Postgres) · 획순 데이터(jsDelivr CDN)
- 사진은 브라우저에서 긴 변 1280px로 줄여 보낸다 (Vercel 함수 요청 본문 4.5MB 제한)

## 9. 성공 기준 (데모 기준)
- 폰에서 배포 URL로 시나리오 1~3이 끊김 없이 동작
- 사진 촬영 → 한자 칩 표시까지 10초 이내, AI 설명 첫 글자 2초 이내
- 테스트 한자 6개(私 必 飛 職 あ ア) 획순 정상, 데이터 없는 글자는 안내

## 10. 리스크 → 대응
- 사진·손글씨 인식 오류 → 항상 후보 목록에서 고르게 + 다시 찍기 안내
- 발표장 조명·네트워크 → 미리 찍어 둔 사진 파일로도 검색 가능 (파일 선택), 데모 녹화 백업
- 시간 부족 → Tier 2부터 준비중으로 전환

## 11. 결정할 것 (grill-me 질문 후보)
- Supabase를 데모에 꼭 보여줘야 하나? → 그렇다면 S2를 Tier 1로 올리고 사진을 Tier 2로
- 홈 화면을 검색으로 할지, 질문(준비중)과 나란히 둘지
- 정확한 마감·발표 시간, 데모 기기
