# 정확도 정책과 기록 (SENSE)

> 교육 앱의 신뢰는 정확도에서 온다. 이 문서는 **무엇을 어디서 가져오고, 어떻게 검증하고, 얼마나 맞는지**를 한곳에 둔다. 숫자는 `ai-eval`·`accuracy-auditor`가 추가한다.

## 1. 정보별 출처 (화면 배지와 같아야 한다)
| 정보 | 출처 | 배지 | 바뀌는 방법 |
|---|---|---|---|
| 음독·훈독·획수·급수·한국 음 | KANJIDIC2 (EDRDG) | `사전 · KANJIDIC2` | 데이터 갱신 PR (`data:build`) |
| 한국 한자 자형·구자체 | Unihan 18.0 (kJapaneseOldVariant, kIRG_KSource, kHangul) | `Unihan` | 데이터 갱신 PR |
| 단어 표기·읽기 | JMdict (EDRDG) | `JMdict` | 후보 목록 빌드 |
| 획순 애니메이션 | hanzi-writer-data-jp 0.8.0 | 페이지 하단 문구 | 전수 점검(`data:audit-strokes`) + 예외 표 |
| 한국어 뜻·단어 선택·예문·팁 | AI (Claude) — 사전 사실 입력 + 검증 | `검수 완료` / `AI 생성 · 자동 검증` / `AI 생성 · 검증 중` | 프롬프트 버전 + eval |

## 2. 검증 규칙 (저장 전 필수) — `src/lib/cards/verify.ts`
1. 스키마 통과 2. 단어가 JMdict 후보에 있고 읽기 일치 3. 예문 한자 전부 후리가나·중괄호 짝 4. 예문에 단어 포함 5. 뜻 판정 ≥ 3/5 6. 금칙(읽기·자형 판단 언급) 없음
실패 → 재생성 1회 → `rejected`(미노출)

## 3. 통과 기준 (바꿀 때 이유를 적는다)
- 결정적 검사 100% · 판정 평균 ≥ 4.0 · p95 ≤ 4초 · 같은 글자 재방문 AI 호출 0회

## 4. 알려진 한계 (화면의 "알아 두세요"와 동기화)
- JLPT 급수는 KANJIDIC2의 구 4단계. N레벨은 참고 자료 기준
- 획순 **순서**의 정오는 자동 검증이 어렵다. 점검한 글자 목록은 `kanji-stroke` 스킬 하단
- 예문은 AI가 만든 문장이라 자연스러움은 판정 모델 기준
