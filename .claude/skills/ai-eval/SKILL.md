# AI Eval (평가를 테스트처럼)

해커톤의 교훈: `職·履·学` 한 번 통과는 운이었다(반복 측정 4/9). **평가 없이 프롬프트를 바꾸지 않는다.** 바꾼 뒤 숫자가 좋아졌을 때만 머지한다.

## 두 종류의 검사
| 종류 | 무엇 | 비용 | 예 |
|---|---|---|---|
| **결정적** (코드) | 정답이 있는 것 | 0 | 단어가 JMdict 후보에 있고 읽기 일치 / 예문 한자에 모두 후리가나 / 스키마 통과 / 금칙 없음 / 응답 시간 |
| **판정 모델** (LLM-as-judge) | 정답이 하나가 아닌 것 | 소량 | 한국어 뜻이 영어 뜻과 맞는가(1~5) / 예문이 자연스럽고 번역이 맞는가(1~5) / 팁이 사실인가 |
판정 모델은 생성 모델과 **다른 모델**(또는 같은 모델이라도 temperature 0, 기준을 명시한 루브릭)을 쓴다.

## 정답 셋
- `evals/kanji-truth.json` — 키트가 제공(KANJIDIC2 3.6.2, 2026-10-26 기준 59자: 취업·일상 한자 + 자형 차이 까다로운 글자). 필드: on, kun, korean_h, meanings_en, grade, strokes, jlpt_old
- 늘릴 때는 `kanji-data`의 `kanji.json`에서 무작위 추출 + 실패했던 글자를 추가(회귀 셋). 실패 글자는 영원히 남긴다
- 단어 정답은 실행 시 kanjiapi.dev(JMdict)에서 가져와 캐시(`evals/.cache/`)

## 스크립트 `scripts/eval-kanji.ts` (`npm run eval:kanji -- --n 30 --runs 2`)
1. 표본 n자 × runs회 카드 생성 (`card-pipeline`의 생성 함수를 직접 호출 — HTTP 경유 아님, 저장은 안 함)
2. 결정적 검사 → 항목별 통과/실패
3. 판정 모델 채점 (뜻·예문·번역) → 점수
4. 시간(p50/p95), 토큰, 비용 추정
5. 결과 `evals/results/<날짜>-<promptVersion>-<model>.json` + 요약 표를 `docs/ACCURACY.md` 하단에 추가 (git에 남긴다 → 추세가 보인다)
6. 실패 사례는 `evals/failures/<날짜>.md`에 입력·출력·사유를 적는다 → 프롬프트·검증 규칙 개선의 재료

통과 기준(초기): 결정적 검사 100%(실패는 버그), 판정 평균 ≥ 4.0, p95 ≤ 4초. 기준은 `docs/ACCURACY.md`에 적고 바꿀 때 이유를 남긴다.

## 언제 돌리나
- 프롬프트·스키마·모델·검증 규칙·데이터 버전을 바꾼 PR → **반드시** (CI `eval.yml`이 `src/lib/ai/**`·`evals/**` 변경에 돌아감. 비용 때문에 n=15·runs=1)
- 월 1회 전체 표본 (수동)
- 배치 카드 생성 후 표본 50자 (`card-pipeline`)

## promptfoo (선택, 보조)
- 여러 모델·프롬프트를 표로 비교하고 싶을 때 `evals/promptfooconfig.example.yaml`을 복사해 쓴다 (`npx promptfoo@latest eval -c evals/promptfooconfig.yaml`, `npx promptfoo view`)
- 학교 프록시는 provider의 `apiBaseUrl`로 지정. 안 되면 자체 스크립트(위)만 쓴다
- `llm-rubric` 어설션으로 판정 루브릭을 YAML에 둘 수 있다

## 루브릭 예 (판정 모델에게)
```
다음은 일본어 한자 X에 대한 설명 카드다. 사전 사실(영어 뜻, 단어 목록)을 기준으로 채점한다.
1) meaningKo가 영어 뜻과 일치하는가 (1~5)
2) example.ja가 자연스러운 현대 일본어이고 고른 단어가 들어 있는가 (1~5)
3) example.ko가 example.ja의 정확한 번역인가 (1~5)
각 항목 점수와 한 줄 이유를 JSON으로.
```

## 실패를 다루는 순서
1. 실패 유형을 센다 (읽기 불일치 / 후리가나 누락 / 뜻 오역 / 부자연스러운 예문 / 느림)
2. 가장 많은 유형 하나만 고친다: 규칙 추가(프롬프트) 또는 검증 추가(코드) 또는 후보 목록 개선(데이터)
3. 다시 측정 → 숫자가 오르면 머지, 아니면 되돌린다. 한 번에 한 가지만 바꾼다
