# Planner (기획)

목표는 **마감 안에 끊김 없이 도는 데모**다. 기능 개수보다 핵심 시나리오 완주가 우선이다.

## 0) grill-me와의 분담
- `/grill-me`(Matt Pocock)는 **질문으로 빈틈을 찾는** 단계다. 결과를 파일로 남기지 않는다.
- planner는 그 합의를 **문서로 고정하는** 단계다. 이 대화에 grilling 결과가 있으면 그 결정을 그대로 반영하고, 다시 묻지 않는다.
- grilling 없이 바로 호출됐다면, 시작 전에 "/grill-me를 먼저 하면 기획이 단단해진다"고 한 줄 권한 뒤 사용자가 원하면 아래 킥오프로 진행한다.

## 0.5) 기능 구상 — 발산 (grill-me 전에, 10분)
"기능 구상", "아이디어 정리" 요청이면 이 단계만 한다.
1. 사용자가 말한 아이디어 + PRD의 문제(3가지 불편)에서 나올 수 있는 기능 후보를 모은다. 사용자 아이디어를 먼저, 내 제안은 3개 이내로.
2. 후보마다 표로: `기능 | 해결하는 불편 | 데모 효과(상/중/하) | 예상 시간 | 위험 요소`
3. 남은 개발 시간에 맞춰 세 칸으로 나눈다:
   - **구현** — 예상 시간 합계가 남은 개발 시간의 70% 이하가 되도록 (나머지는 버그·UX 수정 몫)
   - **준비중** — 화면에 배지 + 안내 시트만 (designer 스킬의 준비중 패턴, 최대 3개). 발표의 "다음 단계"가 된다.
   - **제외** — 오늘은 화면에도 넣지 않음
4. 이 표를 PRD 5장에 반영하고, 사용자에게 `/grill-me`로 넘어가자고 한다.

## 1) 킥오프 (처음 한 번, 10분 이내)
1. `docs/PRD.md`, `docs/TASKS.md` 초안과 이 대화의 grilling 결정을 읽는다.
2. 아직 남은 결정만 **최대 3개** 묻는다. 예: 정확한 마감 시각, 발표 시간, 데모 기기. 나머지는 PRD의 "가정" 섹션에 적고 진행한다.
   - grilling에서 정한 내용은 PRD 해당 섹션에, 정하지 못하고 추천안으로 넘긴 것은 "가정"에 "(추천안 채택)"으로 적는다.
3. PRD를 1페이지로 확정한다: 문제 / 사용자 / 한 문장 해결 / 90초 데모 시나리오 / Must·Should·Won't / 화면 / 데이터 / 성공 기준 / 리스크.
4. TASKS를 확정한다.
   - 작업 1개 ≤ 35분, 각 작업에 **눈으로 확인 가능한 완료 기준**.
   - 마감 시각에서 거꾸로 계산해 체크포인트 2개와 기능 동결 시각(마감 30분 전)을 적는다.
5. 앱 이름 후보 3개 제안 (짧고 한국어·일본어 둘 다 발음 쉬운 것) → 사용자가 고르면 PRD에 반영.

## 2) 진행 점검 ("지금 어디야", 체크포인트마다)
- 현재 시각 / 완료 / 남은 작업 / 남은 예상 시간을 표로 보여준다.
- 남은 예상 > 남은 시간이면: Must를 지키는 방향으로 **아래에서부터** 컷·축소 후보를 제시한다. 사용자가 승인하면 TASKS에 `[-]`로 표시한다.
- 새 아이디어가 나오면 바로 만들지 않는다. Should / Won't 중 어디인지 분류해 PRD에 적기만 한다.

## 3) 규칙
- Must 4개가 배포 URL에서 동작하기 전에는 Should에 손대지 않는다.
- 범위를 **늘리는** 결정은 항상 사용자에게 묻는다. **줄이는** 제안은 적극적으로 한다.
- 결정은 docs/ 파일에 남긴다. 대화에만 있는 결정은 없는 것으로 본다.
